# 钉钉群报修工单系统 · 说明与淘宝对账协作

> 更新：2026-08-12（新流程）· 版本 v4.0

## 一、系统概览

系统监听门店钉钉群的报修消息，自动建档、推进、完成工单，并在群里回复。核心原则：**群内正常沟通即业务**，显式关键词与自然语言都能识别，模型不可用时关键词仍可完成核心操作。

### 技术栈
Python 3.14 / asyncio / SQLite(WAL) / `dws` CLI（钉钉连接器）/ OpenAI-compatible 云端模型（可选）

### 数据（`data/tickets.db`，19 张表）
`groups` `tickets` `messages` `processed_events`（幂等台账）`diagnosis_versions` `repair_method_versions` `timeout_cycles` `notification_deliveries`（Outbox）`inbox_messages`（收件箱）`semantic_decisions`（语义审计）`message_ticket_links` `ticket_contexts` `pending_actions` `action_executions` `schema_migrations` `delivery_confirmations` `taobao_orders` `order_monitor` `responsibility_cycles`

## 二、业务流程（新流程）

```
店铺同事/店长在群里发报修（自然语言或 #报修）
        │
        ▼ 建工单（主题/位置/问题描述，时效缺省 1 天）
工程师或同事回复故障判断 → 记录
        │
        ▼ 提交维修方式 + 淘宝订单号（订单号人人可发）
  工单自动延期 +3 天（每单一次）→ 订单↔门店写入共享表
        │
        ▼ （另一个 AI 每天拉淘宝状态回传共享表）
调度器读共享表 → 状态变化时群内通知一次：
   · 卖家已发货 → 提醒「已发货，留意收货」（不再问签收）
   · 交易关闭   → 提醒「订单因未付款已关闭，请处理」
        │
        ▼
群里回复「修好了」→ 工单直接完成（无需二次确认）
时效即将到期 → 群内提醒一次；超时再提醒一次
```

### 关键动作与角色权限（2026-08-12 更新）

| 动作 | 关键词/识别 | 允许角色 |
|---|---|---|
| 报修建单 | `#报修` / 自然语言 | 店长、其他成员 |
| 补充信息 | `#补充` / 自然语言 | 全员 |
| 故障判断 | `#故障判断` / 自然语言 | 工程师 |
| **维修方式 + 订单号** | `#维修方式` / 自然语言 | **店长、工程师、其他成员（订单号人人可发）** |
| 完成工单 | `#完毕` /「修好了」/ 自然语言 | 店长、工程师（直接完成，无需确认） |
| 取消工单 | `#取消工单` / 自然语言 | 店长（需确认） |
| 重开工单 | `#重开工单` / 自然语言 | 店长、工程师（需确认） |
| 查询工单 | `#查询工单` | 全员 |
| 选择工单 | `#选择工单` | 全员 |

> 订单号提交：任何群成员都可以发订单号，都会触发该工单自动延期 +3 天并登记到共享表。

## 三、淘宝对账协作（给另一个 AI）

### 共享表文件
```
/Users/yushui/Desktop/淘宝对账/订单门店状态表.xlsx
```
表头：`order_id | store | ticket_no | status | tracking_number | updated_at`

### 分工
| 写入方 | 写入内容 | 时机 |
|---|---|---|
| **报修系统（本系统）** | `order_id` `store` `ticket_no` 三列 | 群里提交订单号时追加一行 |
| **另一个 AI** | `status` `tracking_number` `updated_at` | 每天拉淘宝订单状态后回传更新 |

### 状态值（另一个 AI 回传）
| status 值 | 系统行为 |
|---|---|
| `卖家已发货` | 群内提醒一次「订单已发货，留意收货」（含物流单号） |
| `交易关闭`（含未付款关闭） | 群内提醒一次「订单因未付款已关闭，请处理」 |
| 其他（等待买家付款/已付款/交易成功…） | 只记录状态，不通知 |

### 写入规范
- **幂等**：按 `order_id` 匹配，已存在则更新状态，不重复加行
- **读改写**：每次写入前先读最新文件，改完再写，避免覆盖对方更新
- 状态回传频率：每天一次即可（系统每 60s 扫一次表，检测到状态变化才通知）

### 调度建议（给定时任务 AI）
另一个 AI 每天执行「拉淘宝订单状态 → 更新共享表」即可，无需懂本系统代码。示例 cron：

```bash
30 9 * * *  <另一个AI的淘宝状态拉取脚本>
```

本系统侧无需额外配置：只要 `python main.py` 在跑，调度器自动读共享表并通知。

## 四、运行方式

```bash
# 启动系统（PRODUCTION 模式，监听配置的群）
PATH="$HOME/.workbuddy/binaries/node/cli-connector-packages/bin:$PATH" \
  python main.py --mode PRODUCTION

# 运行模式：SHADOW（只记录不执行）/ ASSISTED（模型动作全确认）/ PRODUCTION
python main.py --mode SHADOW

# 手动导入淘宝对账地址表（快递确认增强用）
python -m reconciling.import_orders --xlsx "/Users/yushui/Desktop/淘宝对账/订单地址明细.xlsx"

# 完整流程模拟（假分类器，可重复演示）
python scripts/simulate_flow.py

# 测试
python -m pytest tests/ -q
```

### 环境变量
- `TAOBAO_ORDER_DETAIL_XLSX` / `TAOBAO_PENDING_XLSX`：对账导入源文件路径
- `ORDER_STORE_TABLE_PATH`：订单↔门店共享表路径
- `ORDER_EXTEND_DAYS`：识别订单号后的延期天数（默认 3）
- `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY`：云端模型配置
- `SLA_REMIND_BEFORE_HOURS`：时效提醒提前量（默认 6 小时）
