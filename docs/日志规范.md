# 日志规范 — 钉钉群报修工单归档系统

> 版本：1.0（2026-08-11）
> 范围：`dingtalk_script/` 全部代码，所有关键节点必须打日志

## 1. 工具与格式

- 使用 Python 标准库 `logging`，统一由 `logger.py` 的 `setup_logging()` 初始化。
- 每模块 `logger = logging.getLogger(__name__)`。
- 日志格式（控制台与文件一致）：

```
2026-08-11 10:42:43,123 | INFO  | ticket_manager | 建单成功 ticket_no=滨江店-博物馆奇妙夜-001 group_id=cidO+6f66Jja9EzGTFm3rra1Q== message_id=msgxxx
```

- 输出双通道：stdout（控制台）+ `logs/app.log`（RotatingFileHandler，5MB × 5 轮转）。
- 业务字段（group_id / message_id / ticket_no / sender 等）一律拼在消息文本中，便于 grep 排查。

## 2. 级别约定

| 级别 | 用途 |
|---|---|
| DEBUG | 每条事件原始细节、解析过程、乱序判定细节 |
| INFO | 订阅就绪、进程启停、业务状态变更（建单/字段更新/责任切换/关闭）、配置加载 |
| WARNING | 格式错误、权限不足、幂等命中、非法角色、重连、发送重试 |
| ERROR | 异常、钉钉接口失败、数据库错误、发送最终失败 |
| CRITICAL | 启动失败、角色配置重叠、无法恢复的错误（程序停止） |

## 3. 关键节点清单（必须打日志）

### 3.1 进程生命周期
- 启动：版本、配置来源、监听群列表、日志级别
- 退出：退出原因、各任务清理结果

### 3.2 事件链路
- 收到原始事件（DEBUG：`event_id`、`type`、`message_id`）
- 标准化成功（DEBUG：`NormalizedMessage` 关键字段）
- 标准化失败丢弃（WARNING：缺失字段清单）
- 系统账号回流过滤（INFO：`sender=工程部AI`，is_self）
- 幂等命中跳过（INFO：`message_id` 已处理，result=原结果）
- 角色识别结果（DEBUG：`sender` → `MANAGER/ENGINEER/OTHER`）

### 3.3 数据库
- 连接建立（INFO：DB 路径）
- 建表/迁移（INFO：执行 SQL 名）
- 每个事务：开始（DEBUG）、提交（INFO：事务类型+主键）、回滚（ERROR：事务类型+原因）

### 3.4 业务动作（Phase 2+ 陆续补齐）
- 建单成功/失败及原因
- 关键词解析命中/未命中
- 责任方切换（旧周期关闭、新周期创建）
- 4 小时升级触发（含周末顺延）
- 总时效到期、超时原因提交、延期
- 关闭校验通过与拒绝（列出缺项）
- 提醒发送：成功/失败/重试次数

### 3.5 监听与调度
- 订阅 ready marker（INFO：`subscribe_id`）
- 监听进程非正常退出（ERROR：退出码）与重连（WARNING：退避时长）
- 调度扫描轮次（DEBUG：扫描类型、命中数）

## 4. 脱敏与安全

- `raw_event` 不得完整落盘（含 subscribe_id 等内部字段）；只记录提取后的业务字段。
- DEBUG 级别可记录 `message_id`/`conversation_id`，不记录账号 token 或凭证。
- 消息正文按业务需要记录（系统本身要归档消息），但日志不重复输出大段正文，引用 `message_id` 即可。

## 5. 使用示例

```python
from logger import get_logger
logger = get_logger(__name__)

logger.info("建单成功 ticket_no=%s group_id=%s message_id=%s", ticket_no, group_id, msg_id)
logger.warning("幂等命中跳过 message_id=%s result=%s", msg_id, result)
logger.error("事务回滚 tx=%s reason=%s", tx_name, exc)
```
